# 重構前稽核（2026-10-31）

## UI 與球場
原介面主要面積被標題與留白佔用，步驟字級低至 8–10px。球場為重複線條木紋，缺少完整標線與精準三分線交點；球員僅為直徑 3.3 英尺的圓標。每個 SVG 使用相同 wood/arrow/clip ID，雙球場存在引用衝突。縮放與翻轉未完整納入拖曳逆座標換算。

## 動畫與戰術資料
sample() 只支援兩畫格直線插值；球權變更佔用整段畫格時間，沒有獨立傳球起訖、接球停頓或投籃弧度。追防由對手座標加偏移產生，不能表達繞掩護。PnR 分支雖改變部分座標，但沒有防守方案。沒有路徑、朝向、區域與標註事件模型，未驗證球員相交。

## 工程與互動
App.tsx 混合球場、播放器、資料庫、編輯器與匯出等責任，大量程式擠在同一行。上一/下一步硬編碼兩秒；沒有循環或逐格。RAF 在暫停時仍持續取樣。比較模式主時間軸長度只取左側，右側較長時無法播完。既有測試覆蓋基礎互動，但沒有曲線連續性、防守差異、碰撞與獨立傳球事件驗證。

## 重構策略
保留 localStorage、22 套戰術、比較、球隊頁與編輯器；擴充可選 scene 資料層。拆分純函式幾何、球場呈現、時間軸與 PnR 劇本。示範資料以英尺座標手工編排，所有物件從同一播放時間取樣；其他資料維持基本示意並清楚標記，不能把畫面升級等同於所有戰術內容完成升級。

球場尺寸依 NBA Rule No. 1 與官方 court diagram 核對：https://official.nba.com/rule-no-1-court-dimensions-equipment/ 。三分弧半徑 23.75ft、底角距邊線 3ft、合理衝撞區半徑 4ft，籃框中心距底線 5.25ft。
